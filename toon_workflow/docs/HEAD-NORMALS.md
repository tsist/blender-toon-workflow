# 头部整体法向与单插件工作台（0.16开发版）

法向主要用于头部。脸、眉毛、睫毛、头发、眼部、口部和饰物都可进入同一头部配置，每个网格保持独立权重和强度。所有新部件默认全零权重、强度0，不按名字猜角色，也不把全身网格统一球化。

## 从统一工作台操作

单一插件启用项为「三渲二 · Toon Workflow」，侧栏为「三渲二 → 三渲二工作台」。描边作为内置后端，工作台同时提供整头法向、单部件法向和材质连接、描边作者、镜头修形与联合渲染。内置描边不要求用户另启用一个描边插件。

1. 在「头部整体法向」指定跟随头骨的独立参考物，选择当前一批网格并选择角色（面部、睫毛、眉毛、头发、眼部、口部、附属物），点击加入。可分批加入不同角色。
2. 没有艺术法向字段的部件会建立默认0字段及缺少的全零FLOAT/POINT权重；共享网格先隔离。已有字段保留自己的参考、权重和强度，引用必须与头部参考一致。任何目标不合格都明确拒绝，失败回滚本次创建的数据。
3. 对脸和身体共用一个网格的角色，权重只覆盖头部区域。新权重不会自动设为1；可使用Blender原生属性工具编辑。附属物也各有权重，不依赖共享节点组。
4. 逐部件编辑请求强度，显式预览整头配置。改变骨骼/表情后，实际法向按原生GN逐帧重新求值；后台联合渲染逐帧应用配置。原生参考、权重或强度已有动画时，配置应用拒绝接管，保留作者动画。
5. 选中已登记成员可更新角色或移出；全部移出只清配置，不删除独立法向字段、权重或材质。改名不丢绑定；删除目标或转绑修改器会明确报错。
6. 材质连接位于「单部件法向与材质连接」。先选择活动部件及其独占材质，再绑定唯一且Normal未连接的原生Diffuse。共享材质、已有Normal连接、多Diffuse会拒绝；可先复制材质或在原生节点编辑器中明确接入读取组，不自动改整头所有材质。UI解绑只处理自己创建且未被手改的链接。

首版每Scene一个头部配置、1..64个本地Mesh。七种角色都支持；曲线/Grease Pencil/实例、库链接/Override不是此配置已验输入，不能静默漏掉。多个角色应使用独立Scene或保留独立法向字段，当前不自动推断多个头。

## 法向、修形与投影

艺术法向是原生变形之后、镜头修形之前的世界空间椭球梯度，保原Mesh法向、顶点与二维线分类。它决定着色大形；睫毛、眼球和头发仍需按部件调节，球化不自动生成优秀鼻颊交界。面部SDF、真实头发投影与高光是不同层，完整P5继续开发。

新联合回执包含 `head_normal_config`：真实成员ID派生的身份、角色、参考、请求/实际强度及渲染可见性。可见成员必须与实际RENDER法向冻结见证一致；不可见成员明确标记，不冒充渲染验证。核心配置API为 `head_normals.define / inspect / controls / apply / clear`；无需在UI中输入代码。

## 单一开发安装包

ZIP仅一个根包 `toon_workflow`，内部包含母领域、稳定0.2.27描边源码及公共CLI薄适配。内部按真实包命名空间导入，不给 `toon_*` 建顶层别名，不要求另安装外部描边包。来源与许可随内置后端保留，原稳定源码保持不变。

后台作业继续使用现有公共CLI基础监管。安装在工程目录外时，在联合渲染区选择含 `blenderctl.ps1` 的「公共工作目录」；本机工程为 `<PROJECT_ROOT>`。插件启动其内置CLI薄适配，并调用所选工程的共享监管核心、当前Blender和Python。没有公共目录时明确拒绝后台提交；法向/修形/作者编辑仍是插件内部功能。该依赖不伪装为无公共CLI的独立渲染器。

单包不附私有角色、贴图、Blender二进制或商业组件。开发候选需独立安装、启停、保存冷开与实际后台渲染验收，不因生成ZIP就成为P9正式发行或完整艺术验收。
