# 头发 SDF：八方向循环明暗（0.42 操作合同）

本页描述同一三渲二工作台的0.42可选功能。精确单包身份、角色工作副本、正式 Combined／Line、保存冷开及实际采用范围以当批 DELIVERY.json 为准；本操作说明不代签完整发型或全光角美术。当前处理**头发自身的明暗形状**；面部 SDF 与刘海投到脸上的影另由各自功能控制。

## 1. 与旧 HM 的分工

旧 HM.G 参与 `dot(N,L) + (G-neutral)*map_strength`，属于逐像素的方向受光偏移。它不是本页的距离图，也不能仅改名成为 SDF。旧 HM.R 的阈值高光、独立 R 覆盖遮罩和 B 固定影仍按原语义读取。

新增子域为 `toon-hair-sdf.v1`。它在已有 HM Group 内添加可逆的扁平节点，仅替换原 `shadow_boundary:smooth` 的两个 `lit_raw` 消费者：

- `lit_with_illumination`：控制同一套亮／影色表。
- `highlight_lit`：令现有受光高光也遵循新的 SDF 明暗。

HM 的原 2 输入／1 输出接口、原 R 图、高光覆盖形状与 B 接口均不重解释。统一高光遮罩读取的 `highlight_strength` 节点已经汇集半角、朝向、照明门控、明暗与强度；SDF 继续使用这条权重链，不另加一条高光。新的 `lit_eff` 仍乘原照明近似门控后选色，颜色输出再经过 B 固定影乘法，所以固定影与动态影重合时仍继续压暗。

新影形会改变高光出现的时机；“保留原高光结构与遮罩”不表示高光像素数值永远不变。判断重点是没有第二套亮带，SDF 暗区内不因新增层漏出高光，并与实际亮／影色表协调。

## 2. 八方向与图像格式

每个目标使用八个均匀全周关键方向，不要求影区单调嵌套：

| Atlas | R | G | B | Alpha |
|---|---:|---:|---:|---:|
| 方向图 0–135° | 0° | 45° | 90° | 135° |
| 方向图 180–315° | 180° | 225° | 270° | 315° |

两张均为独立的 RGBA 浮点 EXR，设为 **Non-Color／CHANNEL_PACKED**。Alpha 是第四个方向的数据，不能拿来表示透明，也不能用普通预乘 Alpha 的解释破坏 RGB。前后发各自使用专用 Image ID；即使来自同一路径，也不共用已被 HM、B、遮罩或其它对象占用的图像 ID。

作者输入是八张二值 PNG：白色为亮、黑色为影；另有白色为有效域的 coverage 图，以及目标 Mesh 的完整实际 UV 描述。编译得到的是图像像素网格上的有符号距离场：

```text
d = sqrt(distance_to_lit_squared) - sqrt(distance_to_shadow_squared)
E = 0.5 - clamp(d, -cap, cap) / (2*cap)
E > 0.5 为亮；E <= 0.5 为影。
```

距离在每个八连通 coverage 分量内独立计算，域外只进行受限的最近分量 padding。该分量是栅格 UV chart 的代理，**不是几何发束 ID**；对角接触也可能合并本应分开的几何岛，使用前需核实际布局。常量全亮／全影分量使用有限饱和值；这不保证所有中间方向都有相同的边界移动速度，也不声称世界空间 SDF、C1 连续或任意曲面等距。

编译器保留源 PNG 字节，只新建输出目录和专用图像。EXR 按真实 RGBA 重载，要求每个关键方向在有效 coverage 内重建原二值分类；不能仅检查 R，不能把 PNG 缩略图或文件扩展名当作精度证明。

## 3. 实际 UV 与方向求值

必须先确认目标材质实际消费的 UV，再制作关键影形。当前角色使用已有 `ToonHairHighlightUVFit`，不修改原 UV。UV 层存在、完整描述匹配或编译成功仅是技术准入；还要在实际模型上核对根部、发梢、接缝、镜像／重叠及可见落点。

本批通过实际 RENDER 几何、已验证的相机和近裁剪范围，把模型画面中的影形分类回填到该 UV。最近表面在实际采样点判定，不拿邻近像素中心的平面代替。未被接受的UV采样点和灰区保留已标明初始值；同UV对应另一个表面的独立性须另验，不冒称所有隐藏表面都不受影响。

灯向来自已有 HM 的实际 Sun 世界 +Z。新独立 GN carrier 读取明确头部参考对象的世界变换，以 Gram-Schmidt 后的 +X 为右、-Y 为前：

```text
phase = fract(atan2(dot(L,right), dot(L,forward)) / (2*pi))
wi = max(1 - 8*abs(fract(phase-i/8+0.5)-0.5), 0)
shade = smoothstep(0.5-softness, 0.5+softness, sum(wi*Ei))
lit_eff = mix(old_lit_raw, shade, strength*valid)
```

0° 指参考前方，正向转至右方；shader 不自动镜像 UV。头部参考是明确的真实对象，不能把仅由 armature 变形的头发对象矩阵误当头部朝向。

`phase` 与 `valid` 是独有 POINT／FLOAT 属性，carrier 位于镜头修形之前，几何直通。接近竖直光时，水平投影长度按 `.1` 宽度平滑淡出；极近竖光的 `valid=0`，回到原 HM 明暗。矩阵／引用错误需要报告并拒绝，不能把无效输入的旁路叫作通过。

仍继承 HM 的 EEVEE、唯一可见白 Sun、零简单 Background World、静态能量与颜色等条件。Sun 旋转和头部参考变换由真实求值提供；受光门控仍是该条件下的照明近似，不外推多灯、任意半影、Point／Area、Cycles 或完整顶底光风格。

## 4. 同一工作台操作

1. 在工作副本中选中实际头发 Mesh 及已用 HM 材质槽，核对完整头发和当前高光／固定影基础。
2. 在同一三渲二工作台的「头发 SDF · 八方向循环明暗」区，填写「八方向影形计划」与一个**尚不存在的绝对编译目录**，执行「编译八方向影形」。这只生成并重载图像，不自动绑定材质。
3. 明确选择两张方向图、实际 UV 和「头部方向参考」，点击「连接零层」。界面连接始终从强度 0 开始，先与原画面比较。
4. 点击「读取」，设置「SDF 明暗强度」与「SDF 影界过渡」，再点击「应用」。当前合同为静态作者常量，不在这些 UI 字段上暗设参数动画。
5. 核对完整材质、关键方向及必要中间角度；最终还需看正式 Combined 与白底 Line，确认脸部重点、鼻嘴线、眼层与头发配合。

真实算子为 `toon_hair_sdf.compile / attach / read / update / remove`，不是新 CLI 子命令。后台联合输出继续使用现有公共 `toon-workflow.run / inspect`。

对应核心 API：

```python
compiled = hair_sdf_authoring.compile_plan(context, absolute_plan, new_output_dir)
hair_sdf.attach(context, compiled['images'], actual_uv, head_reference,
                strength=0.0, softness=0.002)
hair_sdf.update(context, strength, softness)
hair_sdf.remove(context)
```

`0.002` 是产品初始过渡值，不是公式图通用最优值。本批角色使用更硬的 `.0006`；在cap256时对应约0.6144个UV texel的过渡，不是固定的屏幕像素宽度。实际UV密度、镜头及输出变化后需重新看影界，不能因数值更小就判为更好。

更换图像、UV 或头部参考前，先移除旧 SDF，再明确重连。读取可以恢复界面当前真实绑定；不能编辑声明或签名来绕过源变化。父 HM 的移除要求先移除 SDF。移除 SDF 恢复原两条 `lit_raw` 连接，保留已有 HM、统一高光和 B；后续合法的其它作者变化不应被旧整图快照盲目覆盖。

如果当前工程已经有 CEL 家族回执，先留存旧家族记录；影形修改完成后，从当前配方合法建立新家族并重新预检／应用，保留旧 CEL 文档和历史回执。不要直接改写旧回执冒充“原样”，也不要为通过 guard 删除原 INDEX 或已绑定线色策略。

## 5. 保护与独立冻结

子域记录父 HM owner、实际目标与原 Mesh、完整 UV 描述、两图完整 RGBA 内容与 Alpha 解释、头部参考、carrier UID／签名／字段及真实 float32 设置。图像被外部消费、原 UV 变化、节点或接缝手改、失联对象等情况应报告冲突。

无 SDF 的旧 HM 继续使用 `toon-hair-map-freeze.v1`；带此子域的捕获使用显式 `toon-hair-map-freeze.v2`。实际 RENDER 见证不仅看对象名或 Sun 世界方向，还读取实际 UV、phase／valid 属性字节、头部参考与 Sun 的求值矩阵，并对照方向 oracle。每次相关 Line／RENDER 采样须重核，保存重开另验，不能把已有世界方向见证当作头部相对相位已经冻结。

强度 0 和卸载恢复需要实际像素验证。操作失败应保留失败记录；若原生清理已越过可精确恢复的边界，必须明确报告回退不完整，不能伪造已销毁的 UID 或把部分产物标为成功。

## 6. 有限证据与制作经验

已回读的 [CORE-TESTS.json](<work/audit/<batch>/>) 为 23 项实际 bpy／RNA 检查，通过了 EXR RGBA 重载、有限真实 RENDER 相位、转头、竖光、卸载图结构／Modifier 恢复和依赖提交后故障恢复。它们是执行检查数，不是独立需求覆盖率。

[PIXEL-TESTS.json](<work/audit/<batch>/>) 为 32×32 EEVEE fixture 的 7 项检查：零强度／卸载 RGBA exact、启用可见颜色影响、Alpha 保持，以及同引擎常量影色 oracle 识别的 48 像素暗区内，统一高光 on／off exact。该 fixture 不代替角色固定 B、全发型或所有真实遮挡验收。

初稿独立影形为45°前发及225°后发。实际B55检查发现右脸发钩含原正面作者视角隐藏面，顶台阶涉及45亮/90暗插值，右外缘则属于后发初值。后来追加实际三分之四机位的45°/90°生图补稿，按真实透视near-plane首交回填前后发。灰区、不可见面和其它key保留原值；不能因八个通道都有数据而宣称八方向全部定稿。来源与覆盖证据见UV-ROI-REVIEW.json、UV-AUTHOR-TRANSFER-v002.json和图源说明。

四连通会把某些斜向细coverage切成单像素分量，8连通CPU实验14项确认了数字连通及隔离正确；但同贴图实际A/B没有消除上述明显块，不能把分组数字改善当艺术修复。关键是回读实际可见UV、相邻方向输入和隐藏面初值，再补作者，不是反复调softness。

背225全暗也不能直接判SDF图坏。本例baseline、关闭Sun投影和只隐藏明确背景三对象的独立studio对照中，实际SDF观察完全一致，而后两者显出设计影形，确认是背景遮住Sun。正式房间版仍保留原gate与投影，studio是另外保存的明确可见性变体，绝不为了显效跳过阴影门控。

每批分别验实际零层、同条件美术前后、相邻关键角、保存冷开原数据、精确ZIP、公共run/独立inspect、Combined与白底Line。源UV/paint/Sharp/鼻嘴线/眼层/面部SDF/R/B/Keys/权重/Actions/骨架保护不能由小fixture代签，详细资格及剩余项由该批交付记录给出。

**UV像素密度也属于适配。** 轮廓落点正确仍可能因每个UV像素覆盖多个画面像素而形成台阶。本批背225交界ROI在1024图上测得屏幕邻点距离中位约2.13px、p90约3.23px，于是按同原UV重新烘焙真实2048位置/法向/coverage，再把原设计图回投，不放大旧遮罩、不改影形或UV。前发仍可保留其已验1024图。分辨率及距离cap变化后数值场不同，不能复用旧通道SHA或旧画面假称exact；实际新渲染才决定是否采用。上述数值仅描述本例ROI，不能当所有模型的通用分辨率门。

**绑定正确不等于映射唯一。** raw1024像素中心审计发现前发58/111585、后发1177/61112个样本有不同局部三维位置共用UV；阈值为各raw包围盒对角长的1e-5，报告UV-OVERLAP-AUDIT.json。该审计不覆盖连续UV或RENDER UV全域，但足以否定“未接受UV值不变=所有隐藏表面不变”。当前仅采用已实际看的有限视角。需要这些共享发片独立受控时，保留原高光/固定影UV，另建经重叠与密度核验的SDF专用UV，再按真实表面重做回投；不能继续重画一张图来掩盖一处UV对应多处表面的冲突。本轮没有修改或添加原UV层。

本方法是项目为当前需求自主设计的可选扩展。研究参考见分发包内 [HAIR-SDF-PROMPTS.md](HAIR-SDF-PROMPTS.md)（审计源为本批 PROMPTS.md）；不是把游戏复刻项目或某份面部教程包装为官方通用头发 SDF 算法。完整三类风格、全部灯角、未见角色和母 WM 仍保持未完成。
