# 完整静态描边模板与显式角色绑定（0.39）

在同一三渲二工作台展开「完整描边模板与角色绑定」。这项功能与CEL材质组合配方并列：它保存完整的自主静态线组、笔刷、局部颜色属性遮罩、链/虚线/amount及元素控制；不只保存线宽和线色。它不包含shader、SDF/HM、图像或UV资产，也不改变模型或材质。

0.39新增独立 `toon-line-template.v2`：当完整静态作者含材质线色策略时，读取操作保存有序的作者RGB、常量节点颜色和UV图像来源依赖。v1读写和原有追加行为保持原义。v2只允许「替换描边并留存旧记录」，防止全局首匹配策略被追加重排；混合来源次序完整保留。材质引用和UV图像的实际使用对象仍列入原有材质/对象角色，不增加隐式同名匹配。

导入v2后，先绑定每个对象/材质/集合角色，再逐策略明确填写目标来源并点击「确认线色来源」：

- 作者RGB来自模板，无需媒体绑定。
- 节点颜色指定目标材质中的节点名、输入/输出方向和接口标识。只读取受支持的静态常量RGBA，允许目标工程使用不同颜色，不复制或改写节点。
- 图像线色选择目标工程**已经存在**的图像，指定实际UV层名及六项仿射 `[a,b,tx,c,d,ty]`，即 `(u',v')=(a*u+b*v+tx,c*u+d*v+ty)`。图像允许改名，像素、尺寸和色彩解释必须与来源一致；同名错图拒绝。必须检查实际模型上的UV落点，不为迁移重写原UV。

UV材质在目标场景中的全部实际Mesh使用者必须与映射后的对象角色精确一致，每个使用者都要有指定UV。额外共享使用者、缺UV、未确认来源或同会话同名替换都停止预检。确认按钮只记录选择，完整预检仍在应用前执行。图像通过假用户留存；失败恢复原假用户状态与完整旧描边，运行时回滚拒绝覆盖后续作者或来源修改。保存重开后核验当前来源内容和UV，不依赖上一会话的临时ID。

v2不携带图片文件、UV数据或材质着色器，不放开笔刷图像map、legacy INDEX绘制、动画和原有拓扑引用拒绝域。当前爱音原INDEX作者不能直接便携化；不要移除原绘制来冒充完整风格还原。技术输入的成功只证明本合同的重绑定机制，未见角色的艺术复用须另外看实际渲染。

在作者工程中填写模板名、点击「读取当前完整描边」，再导出到新的JSON文件。文件以语义角色列出对象、材质和集合引用。到目标工程导入后，所有角色都等待显式绑定：选中对应对象/活动材质/集合，点击该行「绑定当前」。不会按同名自动猜测目标。未应用绑定来自旧会话时必须重绑，同名替换在当前会话内也会拒绝。绑定列表只存名称与会话身份，不增加旧受管Material的指针消费者。

预检后明确选择应用方式：

- 「追加线组」保留当前静态PRESET，添加模板线组；同名组可停止报告或明确自动改名。现有全局线宽/透明度等设置保留，模板的新组和局部控件会并入。追加到相同对象可能叠加出线，须实际看图决定是否合适。
- 「替换描边并留存旧记录」明确开始新的描边作者，完整使用模板控制；此前完整样式和便携控制留在带保留标记的Text中。原工程仍是完整恢复入口，记录不是自动绑定恢复文件。

重复点击应用只核验当前记录。文档、绑定或实际Pencil作者改变后报告冲突，保留后续编辑。要开始下一份模板，可先点「留存记录并开始新模板」。已应用CEL配方的旧回执也会察觉描边作者改变；请先留档，再以新作者显式绑定并应用CEL组合，不改旧回执冒充原样。

本首片只接受自主静态作者。Pencil参数动画、未提交节点树、捕获的native payload、logical旧名列表、对象参考衰减及拓扑缝锚点需显式迁移；当前会拒绝。启用图像map需图像/UV运输与落点合同，当前不随模板搬运。命名OBJECT_COLOR属性在对应原始Mesh检查POINT/CORNER、颜色类型和有限值；实际RENDER支持与美术落点仍须联合渲染核验。属性存在不等于遮罩适合新角色，不能改原UV来凑模板。

模板不会修复其它功能的身份。已有owned材质的对象改名可能使其着色目标快照失效；如确需改名，应按材质/finish API合法恢复并重新作者。描边迁移不能跳过该保护。本批派生例只改未受管房间对象名，保留头脸/受管材质身份和已有换槽状态。

全预检后用原生set_preset和便携控件安装。即使原生安装完成后外包装失败，也恢复旧引用、原始Text字节及完整Pencil状态，仅清理本次明确创建且零用户的owned Text。运行时回滚遇到之后的控件或Text编辑会拒绝覆盖。
