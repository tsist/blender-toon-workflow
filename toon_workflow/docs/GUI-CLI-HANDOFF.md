# GUI 与公共 CLI 交接

工作台将当前场景保存为独立磁盘快照。原工程路径与原磁盘文件保持，未保存编辑不由后台追赶。后台候选完成只表示公共父进程验收通过，必须点击“接收候选”才写入当前作者。

作者样式支持完整 PRESET JSON 与 `toon-basic-line-width-edit.v1` 的静态 BASIC 像素线宽。两种格式使用与 CLI 相同的分流，不自动转换模式。接收期间保留后续对象位移及几何编辑；等待期作者设置、作者动画/驱动、原对象或材质的身份及共享关系改变时，拒绝旧候选。复制场景携带同一 owner 时也拒绝，需从明确目标重新提交。

接收失败会自动恢复作者属性、集合及原 Text/曲线指针；只有作者和非目标检查通过且接收回执持久化后，才显示成功。同一候选在原会话可重复接收，第二次为无写入操作。跨进程不能证明先前 GUI 引用身份，因此允许检查与恢复原作业，接收需从当前场景制作新候选。

“公共检查”对拥有的成功渲染结果检查其 state；其它情况下检查当前快照。本操作不生成新图片。“恢复原快照作业”沿拥有的终态 run/recover 作业的 `toon-workflow-request.json`，创建新提交和新 job，原 source、resources、manifest、implementation 保持。当前 dirty GUI 不会被重新捕获或应用。旧结果和终态保留；实现或依赖改变时由公共合同拒绝，不能重签旧 pin。

取消、超时、进程树与完整前缀恢复由既有公共调度核心负责。禁用工作台只注销自身 UI/计时器及所有权租约，不终止公共 job。重新启用后可从持久 submission 刷新；需要跨重启追踪时，提交后将当前 GUI 另存自己的工作文件。提交目录包含原快照、请求、日志和恢复入口，应保留，不只拷贝最后一张 PNG。

本说明适用于本机 Windows、Blender 5.2.1 与本批精确开发包。运行资格以同批交付矩阵为准；不扩展为任意跨机、网络盘、断电一致性或艺术质量认可。
