## 2026-11-14 后续：保护已采用key的源响应

当前上后方/顶光切片已完成17组双机位/光照实际检查，原顶光鼻部/下颌及既有控制exact保留；最终规则及限定资格见[真实三维面影最新结果](FACE-SDF-3D.md#2026-11-14-最新限定结果原顶光源响应保护)。这是进入同插件正式集成的机制证据，不是0.44.2已有功能或默认替换。

**域按贡献key定义，不能把所有修正都乘同一脸面mask。** 同一高度范围同时限制上后方暗部与顶光提亮会截出下颌亮带；只限制顶光的高度域仍可能删掉另一机位的鼻部原影。若目标是保护原key，先声明其实际源响应的不变量，按同一真实采样检查阴影/soft过渡/全亮域，再验证相邻光角。不要为保住当前像素中心而不断扩高度缓冲，也不要把所有独立小鼻影都误删为伪影。

本例top guard使用原Gtop/Softness，在puretop明确U=0、T=Gtop、phase=.5，且Dtop≥s时保源响应；当前正Softness已实渲，hard和任意输入不自动继承。原UV、图像与FT mix保持；详细失败和正式接入前置保留在本批ART-REVIEW。

## 2026-11-14 增补：上侧逆光的归因与跨方向可表示性

C94/Shot B的L120/+60实际五态已完成。纯SDF皮肤仍有双团块，旁路SDF后消失，隐藏独立鼻片基本保持；接受层退出后恢复上游全脸影，只是团块失去对比，不表示阈值被修好。完整对照见[归因与限制](../../work/audit/<batch>/)。该结论不泛化为所有孤立影形都错误，也不把CPU九tap当作GPU像素或全局UV证书。

**绘制更多方向key前，先检查实际读者能否同时表达目标。** 当前LRUD先混合`T=(1-w)*h+w*G`再作`T>p`比较。对同一表面处过滤后的G，目标亮给下界`G>(p+margin-(1-w)*h)/w`，目标影给上界`G<=(p-margin-(1-w)*h)/w`（仅w>0）；w=0时该方向不受G控制。各方向约束须求交。margin=0检验硬分类；希望完整走出softness过渡时才按实际读者确定正margin。点局部可行不证明全纹理可行，过滤核共享texel、UV消费与多点约束仍可能耦合。

本例六点、五方向的设计假设中，硬分类交集均非空；采用当前softness量级的完整亮/影余量后，一个颊点的前侧光与上后方要求冲突。它只否决该点的该组目标与余量，不能据此宣称LRUD普遍不可用或直接改成其它表示。详见[必要条件探针](../../work/audit/<batch>/)。

原生生图的新110°上经线草案经真实UV回投、保R/B、保顶光texel分类后，左右上侧逆光改善，但中间角仍有鼻颊尖块、前侧光也改变，因此未采用。原稿key、编译、UV分类与过滤后的完整画面分别验收；不以“原key不变”推定所有混合方向不变。默认工程与0.44.2包保持原身份，新候选不得作为已修复配方复用。

### 从点检查扩大到实际消费域

同一组五方向设计假设扩大到实际18,986个正mix皮肤RENDER三角、1,673,185个UV texel centre后，硬区间冲突79,596处，其中full-mix为2,322处；冲突集中在保原前侧亮区与要求上后方整片入影之间。这否决本例这组目标在单G下的兼容性，不否决所有LRUD，也不否定已验UV。没有texel centre的881个微小三角另补centroid/vertex/edge等131,870个样本；centre响应exact不能代签bilinear fragment或GPU。见[实际消费域约束](../../work/audit/<batch>/)及同批SUBTEXEL-ORACLE.json。

一次ADMM未收敛即不输出合格图；非负过滤下的单侧下降充分构造虽保控制centre响应，实图仍产生嘴边断带/亮洞，拒绝采用并停止该路线。独立审查发现proposed-lit误下降的代码错误，v002已修并只作数值验证，不能继承v001图像或称已修复艺术。约束求解、图像编码、实际消费与艺术采用分别判断；不为求解成功继续穷举参数。

**表示不足时增加有依据的光向自由度，先验证原生机制。** 当前研究原型在比较前混合 `S=(1-W(L))*T+W(L)*(phase+D(UV))`，`L`为真实Sun在头部GS基下的三维方向；`D`是共同模型投影尺度的signed key，只比较/压暗一次。14方向键、24正锥重心是本项目设计；六个上后方键暂共一张D，不代表六套独立影形。方向数值C0不证明影形连续，极点退出、三角边界、受影响前侧光仍须看真实图像。原型不是0.44.2的正式功能；具体资格与后续接入见[三维关键影形记录](FACE-SDF-3D.md#三维方向关键影形研究原型2026-11-14)。


共同端点的后续实图提供另一项限制：直接让top作者在所有正mix消费者上全亮，虽消除85/87.5鼻下回流，却把下颌/颈部旧影边提亮；新原型仍不默认采用。顶光目标须分清主要脸面、下颌与颈部，不能把模型外全亮边界当普遍正确，也不能由字段/centre单调证明完整角色画面。先回读原top实际影形与表面消费，再校准作者域；本批具体数值和图像见ART-REVIEW，不作通用容差。

- **原神官方高层披露**：GDC 2021 演讲说明，美术设计面部阴影遮罩，按主光方向调整形状。官方自动字幕没有给出 SDF 编码、距离算法、通道布局或位深，不能由此宣称“米系官方统一 SDF 公式”。[GDC 演讲](https://www.youtube.com/watch?v=-JFyAdI_rO8)
- **星铁与绝区零的可读实现**：Stalo、HoyoToon 等作者提供了具体可检查的复刻。它们采用面部专用阈值、头部方向和独立特征层；不同项目的采样、角度和通道合同不同。它们证明公开实现路线的可行性，不证明游戏内部源码或最新补丁实现。
- **鸣潮官方反例**：常规面影无法满足部分演出，特殊顶光使用专门阴影贴图。应把常规水平面影与特殊纵向光照分开设计。[Epic / 库洛访谈](https://www.unrealengine.com/developer-interviews/exploring-the-post-apocalyptic-charm-of-asg-open-worlds-in-wuthering-waves)
- **最新资料的适用范围**：本轮覆盖截至核验日可访问的 2026 年资料、开源提交及官方素材索引。终末地官方访谈确认定制渲染与制作标准，但未披露面部 SDF；绝区零较新官方开发访谈讨论角色制作，也不能用来补全未公开算法。新发布日期不自动提升技术证据等级。
- **实际看图范围**：主线程实际查看了上述鸣潮访谈的秋水顶光、丹瑾灯光对照两张官方原图。未逐帧观看最新版本官方视频、未在游戏中复测。不能把图像搜索的文字描述、PV 标题或社区截图冒充实机观察。

以下规则是本项目的制作判断。需要确认官方算法时，继续保留“未披露”；需要确认目标画面时，用可追溯的参考与实际模型渲染。

## 2. 先建立视觉目标

爱音的最终设计继续服从爱音官方公式图与选定剧照；借鉴二游的制作方法，不拼接几个游戏的五官与影形。公式图用于身份、五官和线条；剧照用于指定灯光下的明暗；PV 与实机分别标注。单张参考无法准确反推出灯光角度、材质公式或全部光照行为。

开始画图前，保留一张简明目标卡：参考来源/版本、角色与机位、可辨认的主光、亮色/影色、下表各区域的目标形状和不确定项。光角不明就写未知，不凭画面编造角度。

| 区域 | 要确定的画面关系 | 退回修正的典型问题 |
|---|---|---|
| 鼻梁、鼻尖、鼻翼 | 鼻影大小、朝向、与鼻线的间距；是否允许鼻尖亮岛；与参考的鼻形身份一致 | 鼻影细成无意义小点、扩大成脏块、与描边重复成黑环 |
| 眉间、眼窝、眼下 | 阴影怎样承托眼神；何处由形体影、发影或独立眼影承担 | 影边错误切断眼睛；为遮碎影而让全脸恒亮 |
| 两颊、颧部 | 终止线的弯曲、转折和留白；有无有意亮区 | 几何碎三角、突变凸包；机械追求直线半脸 |
| 嘴、下巴、下颌 | 嘴线与唇下影的主次；下巴转折及颈下关系 | 嘴线被材质吃掉；影边误读成第二张嘴 |
| 额头、发际 | 面部大明暗与刘海投影的关系 | 把刘海投影画死在主 SDF，或多层重复压暗 |
| 整体 | 明暗块面积、负形和五官可读性；与发色、描边、背景的协调 | 单看纹理漂亮，合成后五官失去重点或出现两套边界 |

**不设置通用造型禁令**：伦勃朗三角、背光鼻尖亮点、连通的半脸阴影都是可选设计。鼻子可以进入阴影，眼窝可以有重影，特殊顶光可以出现多边形亮形；是否采用由目标参考决定。不能把“某角必须半脸”“所有孤岛都删掉”“鼻子不能投影到脸颊”当普遍规范。

影色和轮廓同样重要。使用目标色表或有依据的偏色，结合环境保持明暗可读；不靠乘纯黑或提高 Emission 抹平所有光照差异。

## 3. 选对能表达目标的模型

面部常称的 SDF 贴图，在此通常是**由距离场辅助生成的角度切换阈值图**。运行时存储/读取的是每个表面位置的入影时机，不能把它等同于三维空间距离场。

| 方案 | 适用条件 | 能力边界与决定 |
|---|---|---|
| 一个方向分支的一张入影阈值图 | 固定主光方向分支内，各像素最多一次亮→影 | 简洁可控；不能表达同一像素暗→亮→暗 |
| 单图加采样镜像 | 目标影形可对称，且实际 UV 镜像映射成立 | 不是所有脸都必须对称展开；只因底色妆面不对称，也不一定要重做影形 |
| 左右独立图/通道 | 两侧影形需要独立设计，或单纯翻 U 不成立 | 必须处理前后汇合处；当前读者不支持就列为功能缺口，不能假装已经接入 |
| 特殊顶/底光、区域门控、多图或二维方向响应 | 水平一维阈值无法满足选定镜头 | 先做最小可验证方案；选择与过渡需显式，不随相机暗中换图 |
| 独立特征/投影层 | 鼻嘴线、眼影、真实或美术发影、非单调局部影形 | 与主面影分工；并非强制每个五官都另开材质或贴图 |

若定义 `shadow(p,u) = [T(u) <= p]`，则在**同一分支**内必有 `S(p1) ⊆ S(p2)`（p1 < p2）。这是单阈值表示的数学限制，不是所有方向、顶底光或艺术阴影的普遍规律。多个有意独立影块仍可合法存在。

关键图发生影→亮冲突时，先判断作者误画还是表达模型不足。不得自动 union、累计截断或扩大模糊把冲突藏掉。若目标本就非单调，改用合适分层；不是无限加 key。

## 4. UV、方向与解码合同先于贴图

### 4.1 实际消费 UV 是首要条件

先确认对象/已用材质槽、真实纹理读者、UV 层、Mapping、coverage，以及原始与 RENDER 求值的表面对应。定位鼻、眼角、嘴角、下巴和额头，识别重叠岛、镜像岛、缝和非目标区域。

可以在固定头部画布上设计，再有依据地转移到现有 UV；也可以直接在真实 UV 上作者。两者都必须回到实际模型验落点。附 UV 底图给生图、记录 UV 名、或图像在平面上看起来对，都不等于配准完成。不得移动原 UV 来迁就新图。

落点存疑时暂停重画，用实际RENDER面角UV与相机投影建立同点编号对照：一边是消费UV线网，一边是完整材质画面，核鼻部、眼角、嘴缝、下颌等本次相关区域。锚点应从真实几何/UV提取，不凭画布大概位置手放。区分几何点、最终可见线和遮挡；纯阈值示意不包含区域mix/上游影，不要求与最终影区逐像素重合。

角色固定左右、观察者左右、光位左右、图像 Y 向下与 UV V 向上分别记录。用可辨认且可撤回的诊断标记检查，不只用对称图判断。只有已证明对应关系时才使用 `1-U`；左右图已在头部空间镜像并烘焙到原 UV 时，不再翻一次 U。

### 4.1.1 侧背上光横带的归因（2026-11-15）

0.45的新增32图在L135/+30、+45等处发现眼下横向亮带，艺术不通过，原正式资格不扩展。固定L135/+45、C−25/0六态的基线EXR与原问题图exact；实际相机/Sun、八字段全数组和局部坐标跨态一致。T-only无同样横带、Dupper端点仍有横带；SDF旁路扩亮主要脸面，接受层旁路使其变暗，不能把吞掉横带当修复。该结果支持优先修方向作者端点及层间组织，不证明UV错误或普遍否定LRUD。

皮肤RGB诊断只解释实际皮肤样本，不能把其他材质、轮廓AA或显示PNG当纯AOV。编码后再解码的精度须相对softness检查；本例half级读回不能验证近阈值精确恒等式。静态单通道最大值也不能代签当前LRUD混合后的全域符号；父审依据实际T-only侧缘亮区否决了“全T−phase为负”的独审推断。

六upper暂共享D，因此U=Σwi丢失端点身份。后续独立方向源须保明确key→来源/通道/实际UV/单位，不从总和猜回方向；新增Di同单位不等于旧残余(T−phase)也成投影距离。先做一个有可见改善的方向影形及邻角双机位，再扩来源和正式身份。共用浅U形、全局移图、扫权重/phase/softness均不作为此归因后的默认修法。

保留作者稿的完整二维亮暗结构；仅在目标确实是单值上下边界时才提取y(x)。窄侧颊受光等目标不能无说明压成一条斜切边。生成稿的坐标只作候选：以当前实际表面轮廓配准，再回投真实消费UV，逐机位核已选三角与UV；画布、非皮肤与域外延拓的黑白值按距离场用途声明，不能让白背景自动变成脸缘漏光。

证据：`work/audit/<batch>/`及`diagnostics-v001/CONTRIBUTIONS.json`。该批尚无新生产blend/包/正式Line资格；头发保持法向/R/B。

### 4.2 角度轴、极性和端点必须匹配

明确光向是“表面指向光源”还是相反；头部正交基应来自实际脸的方向，不是随意套用角色根或相机。无需为此修改 rig；静态任务可使用明确冻结的头部坐标基。

θ 是选定左右分支内的水平无符号方位角：正前为0，正后为π；分支另按有符号 yaw 选择。两种常见进度都可用，但贴图必须按同一轴制作：

| 水平方位角 θ | `p_angle = θ/π` | `p_cos = (1-cosθ)/2` |
|---|---:|---:|
| 0° | 0 | 0 |
| 30° | 0.1667 | 0.0670 |
| 45° | 0.2500 | 0.1464 |
| 90° | 0.5000 | 0.5000 |
| 150° | 0.8333 | 0.9330 |
| 180° | 1 | 1 |

相同灰值 0.25，在这两套轴下分别对应 45° 与 60°。只看 90°会漏掉错误。转换时对**阈值也作同一单调变换**，不能只换 shader 的光角公式。还要核比较方向、等号、偏移、强度与 Softness；非线性换轴后，同一 Softness 数值通常不能保持原角宽，需重新标定。来自其它作者的 alpha/R 通道不直接套当前公式。

0/1 可以是普通端点，也可以被格式保留为恒影/恒亮哨兵，必须按真实消费合同判断。带 softness 时检查端点是否半亮；0.40 bundle-v004实际读者为`lit=T>phase`或正Softness下的平滑比较，没有0/1恒态特殊分支（2026-11-13实际代码与编译报告已核，旧说明已纠正）。不能凭外部工具文档推断。光接近头部正上/下方时水平投影退化，必须有明确、稳定的处理或标注未支持，不能归一化零向量后继续交付。

## 5. 制作流程：先画可读的形状，再编译数据

1. **隔离贡献**：保留源检查点，分别查看主面影、投影、眼层、鼻影面片、鼻嘴线和完整材质。先确定问题来自哪层。
2. **建立关键形状**：按目标参考，先在实际模型的目标机位上定选定光向的黑白二值形状，再通过已验证的表面对应回填/烘焙到消费UV；也可直接在UV作者并立即投回模型审核。关键角围绕鼻颊、眼窝、下巴的重要变化布置，允许非等距；不照抄工具默认 key 数和旧案例角度。单独UV上的光滑曲线不构成模型影形通过。
3. **生图用于作者候选**：需要新美术纹理时使用原生生图，提供实际 UV/面部对应、固定身份、明确左右及该 key 的亮影目标。先审核形状与落点，再作明确二值化/清理；保留生成原件、派生步骤和采用范围。不要让生图直接猜一张“数学正确”的灰度阈值图。
4. **检查表示能力**：逐 key 对齐、核覆盖与相邻嵌套；有意独立影块按设计保留。冲突先解释再处理。
5. **编译与核回读**：用已验距离变换/插值方法计算阈值，按实际格式量化，再由真实解码重建 key。检查关键轮廓以及未参与作者的中间角；距离插值不保证边界移动速度连续或自动有美术质量。
6. **绑定消费链**：在工作副本合法绑定实际材质/UV/图像，核色彩空间、通道、镜像、过滤与 coverage/padding。按现有作者保护合同更新，不手改旧回执。
7. **先验明暗，再验最终风格**：诊断图通过后，必须看目标相机完整材质与 Combined/白底 Line。必要的灯扫用于风格观察，不制作角色动作或修改权重/接触。

### 硬边、精度和过滤

默认追求目标参考的清楚影形；本用户倾向更硬的过渡。分别区分：作者轮廓是否正确、阈值场平滑是否改变时机、shader softness 是否扩宽明暗带、屏幕抗锯齿是否足够。先保证轮廓，后做必要抗锯齿，不靠大羽化掩盖错形。

阈值是数据。RGB 数据图按 Non-Color 读取；混用颜色/alpha 的外来打包纹理需逐通道确认，不能整图盲改 gamma 或预乘。高位深可改善时机量化，不能提高空间分辨率、补回原始灰阶或修复 UV。

作者母版可优先保留 PNG16/浮点及配方；实际导入、压缩、mip、过滤、缩放和目标画面尺寸仍须验。8 位不是自动不合格，16 位不是行业通行保证；不普遍禁用 mip，也不默认任何压缩安全。源 PNG 无瑕不代表最终采样无瑕。

## 6. 面影与其它光影的配合

主面影控制脸的大块明暗；头部法向可辅助其它部件与选定局部，不替代已设计的面影。鼻嘴描边的存在与粗细按独立线条功能控制，鼻影面片按其真实材质角色控制，不能靠 SDF 小粉点代替线。

发影与面影可以有意重合。问题是同一光影贡献被重复计算，导致过黑或出现两条不应存在的边界。按明确的阴影权重/影色合成策略处理；不能禁止一切重叠，也不能默认全部相乘或全都取最大。现有原生 cast 的碎影先从其来源修正/接受策略处理，追加 SDF 压暗无法把已有黑块提亮。

对补光、环境色和夜景，明确谁驱动面影、谁调颜色/填充。当前优先一个稳定的角色主光驱动阈值，避免多盏灯各自生成一张互相争抢的脸影；若采用多光方案另行证明。环境联系、轮廓光、鼻颊高光和发丝高光分别检查，不能以全脸恒亮作为默认修复。

顶底光按需求选择独立特殊影形或其它有据方案。水平投影方案对同一方位的仰角不敏感是模型边界；并不意味着顶底光永远不该改变脸，或所有公开复刻都完全忽略仰角。对极端光位先明确目标，再选择技术。

## 7. 验收矩阵与通过口径

按本次交付范围取样，不设无依据的固定角度数量、三角色配额、4K 门槛、影区面积比例或像素容差。角度取样覆盖变化最敏感处；支持整圈才验整圈，单镜头资格明确保留其限制。

| 验证 | 必须观察的事实 | 不构成通过的替代物 |
|---|---|---|
| 身份与消费链 | UV、槽、通道、左右、解码、色彩与当前文件一致 | 仅有文件名或相同尺寸 |
| 核心形状 | 关键光向鼻/眼/颊/嘴/下巴与选定参考的主次关系 | key 重建误差为零 |
| 中间角与连续灯扫 | 突然凸包、碎块、停顿、倒退、接缝；有意变化应可解释 | 离散几张美图或无限加 key |
| 左右与前后汇合 | 两侧分别检查；对称路线核实际镜像；完整转光核接缝 | 单侧或对称正面图 |
| 特殊纵向光照 | 顶/底光及水平投影退化；目标未覆盖的范围明确标注 | 宣称一张水平图全能 |
| 分离变量 | 灯/头部基准/相机分别变化；主面影不能无故跟相机漂移 | 所有变量一起改后猜原因 |
| 分层合成 | 发影/眼层/鼻影/鼻嘴线与面影协调；开关层核真实贡献 | 只看隔离 SDF 黑白图 |
| 目标输出 | 最终图像尺寸与代表性远近，实际材质 Combined/Line 看图 | 纹理缩略图、注册成功 |
| 持久性与保护 | 保存冷开、依赖与绑定仍有效；原UV/paint/Sharp/rig等非目标数据保护 | 文件存在或作业 FINISHED |

分别记录技术完整性、源数据保护、视觉风格、适用光照/镜头范围的 pass/fail/not_run/not_applicable；写明实际看过的图像与残余问题。某一项通过不能抵消其它项失败。纯文档研究不伪造新的渲染证据。

### 失败分流

- 左右错/跨五官：先查 UV、镜像与坐标，不先动灯。
- 侧光正确而前光过早大片入影：查角度轴/极性/图内时机，再审 key 形状；不只全局平移 phase。
- key 很好、中间角突变：查嵌套、配准、距离插值及量化；若目标非单调，换表示。
- 灯扫正确、最终脸仍脏：隔离真实 cast、眼影、鼻影与 Line；不重画无关 SDF。
- 图在远景闪烁/色带：查真实过滤、压缩、mip、采样和屏幕抗锯齿；不先扩大影形。
- 顶光失控：查水平退化与方案覆盖；需要专用纵向影形就明确开发，不死调水平图。
- 同类修正两次没有改善：回读来源、检查贡献层与可验证假设；停止原参数穷举路线。

接下来的制作顺序：
1. 用爱音官方参考制作区域目标卡，先定鼻影尺寸、鼻嘴线与眼颊留白；已有结果逐项标差距。
2. 核当前图/读者的真实 UV、镜像与角度合同，复用已通过的技术证据。
3. 只重画与目标不符的关键形状，审核中间角和两侧；需要新图时按第5节生成作者候选。
4. 先在最能区分方案的完整材质画面验收，再扩展必要灯扫；避免一次换材质、法向、描边、灯光后无法归因。
5. 若目标超出当前一维/镜像方案，先做独立的最小功能切片与实际输出验证，再接入同一个 Toon 工作台。不得假称已支持，不增开第二套插件。

当前完整三风格、跨角色和母 WM 剩余阶段继续保持未完；本次完成的是研究与制作标准。所有后续执行写入指定母任务 `wm-<date>-<topic>`，不误用其它线程的当前 WM 指针。

## 10. 视频补充：区域响应、共享控制和艺术光向

来源：[腱鞘炎《如何消除CG感》中文视频 BV1pJwwzNEDk](https://www.bilibili.com/video/BV1pJwwzNEDk)。画面明确为BlenderFes **2024AW**、实际演示Blender **4.1**；中文版本由双雷交火发布。不是2026年新版本实机教程。主线程读面部段全时轴5秒采样和全部对应字幕，另有独立原帧复核；眼部/头发由分段读者核读。完整范围、未读帧与来源性质见本轮VIDEO-STUDY，不以准备了1fps图声称全部逐帧读完。

### 10.1 先画模型影形，转换工具不替代美术

03:38–05:52的顺序是：3D绘画时直接看模型上的二值影形，编号导出，用SDF工具插值成灰度阈值图。作者示例8张、等间距，明确数量可随所需精度改变；没有公开具体转换器/算法。更多key只增加作者约束，不保证错误UV、非单调目标、曲面投影或不佳形状自动变好。当前已实现编译器继续复用，不因本视频重写内核。

### 10.2 同图不同区域可有不同响应

05:54–06:48区分：皮肤终止线平滑移动；眼白及需要同样处理的眼部区域在选定时刻整块切换。作者从对应眼部附近取灰值，**用这个有限常量填充相关UV区域**。这不是把阈值输入统一写成0或1；0/1指比较后的亮暗状态。

若当前读者为`lit = T > p`，常量`T_eye=c`意味着同一区域在`p=c`附近同时切换；正Softness时可整块同时过渡，仍不会在眼白内部扫出一条暴露凹眼结构的终止线。图像过滤跨岛、padding不足、区域mix变化、真实发影和独立眼影仍可能破坏最终整块性，需按实际消费者检查。采用与否由该角色目标决定；原眼白、虹膜、高光与睫毛均不因研究自动改图。

5.2.1隔离EEVEE实验已确认变化皮肤阈值与常量眼白响应，以及保存重开后的共享控制；证据`work/audit/<batch>/`和四幅PNG。仅有限内部阈值、平面夹具，不授予生产角色或端点哨兵资格。

### 10.3 同一头部统一进度，颜色仍独立设计

06:51–09:43：阈值图控制选择，亮/影颜色贴图控制色彩；同一头部的皮肤/眼部等阈值材质共用控制源。共享控制语义不等于绕过现有独占图像、owner和冻结保护。实际生产应核参与者、phase/side/valid与区域mask；无须强制所有材质共用同一Image或同一受管组实例。

教程Value **0..2**是一圈，当前0.40是带左右分支的phase **0..1**；角轴、极性、回绕和镜像先适配，不能复制一个数字或驱动器系数冒充兼容。

### 10.4 自动跟灯与美术方向各有用途

07:18–08:26演示驱动器关联Sun_R旋转；10:28–11:58解释也可直接作者Value，作者更常为短镜头手动选择面影位置。这里可复用的是“面影方向是可编辑的艺术参数”。本项目AUTO继续按真实头部基准与主光求值；若目标镜头需要ART模式，须显式记录控制模式/作用域/值/恢复方式，并通过现有动画和冻结合同验证。**本轮未实现新模式**，不静默冻结面影、跟随相机或修改角色动作来过关。

### 10.5 眼层、头发与SDF分工

眼影网格的遮挡/绘制顺序、睫毛/虹膜/高光、头发法向和透光属于独立贡献。教程的Alpha Blend排序与禁发影是特定版本/作品的做法，原生顺序、旧Shadow Mode与4.2+选项不能直接当5.2稳定接口。当前发影B×动态影、原眼层及非目标数据继续保护。最终脸脏或眼神不清时先定位贡献，不重新生成整张SDF。

## 11. 必须可裁决的质量门与停止条件

### 11.1 开工只需一张目标卡

每个当前切片记录：固定源/相机/帧/实际灯与头基准；参考来源；目标区域及其表面/UV对应；该区域应移动还是整块切换；要改变的可见缺陷；必须保留的鼻嘴线、眼神、发影、配色与轮廓；允许改的唯一贡献层。角度未知写未知。先由执行者审图形成具体目标，不新增逐步用户确认门。

### 11.2 四道门分别签字

| 门 | 完成后才能进入下一步的条件 | 结果记录 |
|---|---|---|
| A 归因 | 用已有同条件分层图判定纯阈值、mix/valid、上游/接受层、鼻片、眼层或Line中的贡献；缺证据只补能区分假设的一项 | `diagnostics=complete/partial`与`attribution=assigned/unknown`分开 |
| B 作者与表示 | 模型上的关键黑白形状可读且符合目标；落点有效；区域响应明确；嵌套冲突有解释；当前表示能表达 | 作者形状`pass/fail`，不能以重建exact代签 |
| C 数据与消费 | 实际UV/左右/通道/Non-Color/轴/端点/过滤/消费者/同步有效；编译回读、保护和冷开按变更影响核 | `technical=pass/fail/not_run`，有效旧证据可复用 |
| D 画面采用 | 指定尺寸的完整材质/Combined及白底Line，关键角和敏感中间角无新增无意碎块/跳变；鼻眼颊嘴主次清楚且比基线改善；不吞鼻嘴线，不靠大羽化遮错形 | `art=accepted_current_scope/partial/rejected`，附镜头/光照范围 |

影区比例、像素差、连通性、单穿越、key数量和文件成功只是辅助证据，不能代替D门。几何/Line/Alpha“exact”的要求仅用于本次本应保护的通道，不把所有风格修改都要求RGB零差。眼白整块切换是区域目标选项，不变成所有角色一律要求。

### 11.3 防止无限返工

1. 同一目标、输入、机位和评判口径下，每次只提出一个归因假设和对应最小修改；记录实际改善或新增缺陷。
2. 同类修改连续两次未改善，冻结该组key/phase/softness/过滤参数，停止第三次同路微调。先确认目标本身是否真需修复，再转贡献层、表示能力或采样/表面对应分支。
3. 转支后做一个能决定路线的最小验证；仍无有效进展，记录`rejected_current_candidate`或`blocked_by_named_gap`，保留恢复基线和具体缺口。后续非依赖工作可继续；**不得把未解决缺陷改写成采用，也不删除原需求**。有新证据再恢复。
4. 通过当前局部范围就结束该切片并进入下一依赖项，不自动扩大到全光角。全光角、特殊纵向、跨角色与完整CEL/GAME/MANGA继续独立未完。
